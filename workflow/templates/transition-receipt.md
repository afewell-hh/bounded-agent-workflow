# Transition receipt

Use this shape for a milestone, handoff, or takeover record in its GitHub issue or the
external execution record. Do not create one source-repository file per transition.

Role / assignment generation / session identifier:
Ticket / phase / approved revision:
Policy / CLI versions / model selector, where actually known:
Base / candidate / last verified checkpoint:
Relevant recent commits / staged / unstaged / untracked / other worktrees:
Dirty-work preservation reference, exclusions, unattributed changes and unknowns:
Last completed verified operation:
Current operation and whether any process is still live:
Children and disposition (joined, cancelled, running, or unknown):
Runtime instance / actual source-build-config-fixture identity / health:
Preview access and hold; supervisor/owner; tunnel versus server reachability:
Shared resource reservation/generation, remote jobs, verified/uncertain side effects:
Environment disposition (preserved, released, quarantined, or unknown):
Budget used / remaining and predecessor run:
Evidence pointers and their availability:
Accepted decisions since the last checkpoint, with provenance:
Unverified claims / pending questions / environment constraints:
Next permitted action and what requires human approval:

For a receiving agent, add a concise reconstruction of the observable goal, relevant
invariants, and what it must not do. Flag mismatches against current Git/GitHub/runtime
records. A receipt is a summary of evidence, not a replacement for it.

Access continuity (references only): selected credential-profile/version aliases, consumers,
permitted remote targets/actions, missing/expired status, copies owned by this run, and
preview retention. Never paste values or raw environment dumps. For direct CMS/API work,
include sanitized remote revision/job references, uncertain effects and next safe query.
GitHub: actual human approval provenance versus model findings; any effective-rule blocker.
Changes in secret material/target require explicit reconciliation, not an assumed safe resume.

Closeout continuity: adopted completion mode, integration target, exception holds,
PR head/base/reviewed candidate, actual merge/queue/result state, post-merge gates,
issue closure and next-scope authorization status. Do not replay an uncertain merge.
GUI continuity: accepted intent, captured build/state/viewports, images actually inspected,
baseline disposition, unresolved visual questions. A stored path is not image inspection.
